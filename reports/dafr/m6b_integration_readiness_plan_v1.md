# M6B real-data integration readiness — planning only

7 November 2026. This plan does not authorize M6B, any new observations, retrospective drift analysis, confirmation execution, model refitting or detector-driven selection changes.

M6A establishes a typed, causal persistence-error monitor with separate horizons, robust current-era normalization, recent genuine support, cooldown and explicit telemetry resets. It provides engineering evidence on deterministic fixtures only. The absence of statistical false alarms in those fixtures does not establish a real-data false-alarm rate; h=1 missed a CPU-level step and the minimum support prevented an early change from alarming.

Before integration, approve a separate execution configuration identifying source forecast/outcome ledgers or registered fixed-reference backend, exact source/version/checkpoint hashes, machines, permitted origins/targets, reference availability and source selection cutoff. Reject adaptive-policy losses as reference inputs. Keep source forecasting and detector events separate. A fixed ARIMA reference or changed persistence implementation requires a separately declared input/version contract; current M6A admits only `persistence/rule_v2`.

The original research proposed CPU-level and error channels plus watch/response rules. M6A implements only the error channel. Decide explicitly whether a CPU-level channel is required, how the two would combine, and how alerts differ from genuine concept-drift evidence. Do not interpret the level-step miss as permission to add a favorable posthoc detector without a new design/version.

Freeze the exact normalization source and cold-start convention. M6A uses the first 32 online genuine reference errors per era and a 64-recent-error gate; the original research proposed an initial-prefix scale. These are not automatically interchangeable. Any initial-prefix error normalization must use genuinely causal, out-of-sample reference errors, not fitted residuals or complete-series scalers. First-window contamination, scale floors and correlated errors require development evidence on separately permitted data. No M4A/M5B-2 outcome search is authorized by this plan.

Heavy clipping, repeated alarms in one persistent regime and warnings after benign telemetry gaps must remain measurable. Prespecify clipping diagnostics, alert-rate/false-alarm budgets, whether/when rebaselining is allowed, and how cooldown expires without genuine samples. Changing the rearm/normalization rule changes the detector and needs a new version; never erase inconvenient alarms or labels retroactively.

Keep original five-minute positions, exact h=1/h=12 targets, age-three reference availability, fourth-missing era resets and old-era outcome exclusion. Genuine zero error is valid; missing targets and failed forecasts supply no residual. Track recent support separately from lifetime outcomes and elapsed time. Normalization's 32 errors are included in the 64-error minimum, not 32+64. This gate is separate from M5A's frozen 100 matched pairs and future policy-specific interval support.

The planned 230-tick warm-up can theoretically contain 229/218 genuine persistence errors at h=1/h=12 if its reference is immediately available and every exact target is genuine. Gaps, failures and resets can make this insufficient. Record unavailable detector states rather than lowering support after viewing final results. Source delivery-delay assumptions remain zero extra delay at grid labels; real late arrivals/revisions need explicit new semantics rather than backdated errors.

If a future alarm is allowed to influence a selector, shorten memory or request retraining, prespecify that response as a separate controlled ablation. Preserve fixed persistence, fixed ARIMA, fixed XGBoost and frozen adaptive-only controls under the same quality wrapper and scoring masks. False alarms may harm forecasting; M5B-2 already showed that adaptation can be worse than fixed ARIMA. Detector alarms alone do not establish a useful response or a DAF-R accuracy benefit.

M4A and M5B-2 are inspected development evidence. A later alarm replay there must be labeled retrospective and cannot become independent confirmation. New global settings need designated development evidence followed by untouched independent-machine evaluation. Preserve nominee roles/reserve order and original strict-v1 rejection; development qualification does not automatically qualify confirmation machines. Freeze eligibility, exclusion, normalization, thresholds, support/timing, response and cost reporting before any confirmation forecasting outcome, then require explicit execution authorization.

Readiness: the component can be reviewed for a separately scoped real-source adapter or synthetic response-integration milestone. Research execution remains conditional on source provenance, qualified evaluation data, a globally frozen protocol and explicit approval. No real-data drift performance claim, M6B execution, M7 intervals or dashboard work follows from this document.

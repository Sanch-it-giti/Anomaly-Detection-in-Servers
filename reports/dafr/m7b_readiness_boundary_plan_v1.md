# M7B readiness and evaluation boundaries — planning only

M7A's engine has a deliberately strict deterministic SyntheticForecastV1 input contract, not permission to accept arbitrary real-backend objects. A separately authorized M7B should first integrate the interval engine with registered real ARIMA/XGBoost backends on generated synthetic observations, following M6B's typed provenance gates. It must retain original point centers, selection and drift alarms exactly. A validated new real-backend bridge/version is required; do not weaken the M7A contract or relabel a synthetic fixture as real research evidence. No model fitting during replay; historical checkpoints remain immutable. Any pre-replay fixture checkpoint build must be explicitly scoped to generated data.

For later policy comparisons, retain each policy's own interval availability and genuine-target denominators, and additionally report coverage/width/interval score on a declared common genuine-available target mask. Do not interpret different availability masks as accuracy or reliability superiority. Keep warm-up/insufficient-support, missing, pending, fallback and abstention counts visible, including unfavorable periods.

Preserve both90/95 levels, minimum100/capacity288/288-tick age, exact integer order statistics, complete-policy attribution, raw unclipped bounds, original fourth-missing resets and old-era score exclusion unless a separately reviewed scientific version changes them. Adaptive and fallback intervals belong to their actual complete policy's errors, not whichever expert interval looks narrowest. A changed real model version needs an explicit calibration continuity/reset policy and honest post-change availability, not silent reuse or favorable retrospective recalibration. Keep metadata provenance, checkpoint/scaler/model hashes, exact target/horizon, source-policy version and support fingerprints in immutable ledgers.

Synthetic coverage does not establish real-world calibration, exchangeability, conditional reliability, or improved DAF-R performance. Expanding residual variation can under-cover; shrinking variation can leave wide intervals; gaps, failures and initial support can make intervals unavailable. Detector misses/repeated alarms and M5B-2's unfavorable adaptive finding remain. Reliability-based expert gating, detector-triggered buffer resets, ACI, rebaselining, model refits and physical clipping are new interventions and require separate prespecified designs/ablations. None is enabled by this plan.

Research calibration[1612,1842), final[1842,2304), confirmation machines and all new Alibaba observations remain closed. Any later real-data interval evaluation requires an explicitly named permitted development block, qualification, source hashes and settings frozen before outcomes are opened; it must not be called independent confirmation if previously inspected. No tuning against M4A/M5B-2 or later inspection followed by an unbiased claim on the same targets. Freeze support/exclusions, policy/version handling, physical bounds, horizons, metrics, resource limits and availability denominators before authorized execution; report all unfavorable outcomes. M7B is not started or authorized by this document. No LSTM/dashboard follows automatically.
